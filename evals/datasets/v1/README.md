# Eval datasets (Stage 09)

`v1` holds the seven core scenarios from `docs/EVALS.md`:

- SCN-001 slow database → `database_latency` (payment-service)
- SCN-002 pool exhaustion → `db_pool_saturation` (payment-service)
- SCN-003 bad payment deployment → `bad_deployment` with approval-gated rollback
- SCN-004 inventory upstream timeout → `upstream_timeout` (inventory-service)
- SCN-005 CPU saturation (simulated bounded work) → `cpu_saturation`
- SCN-006 high error rate (deterministic simulated errors) → `application_errors`
- SCN-007 healthy → `root_cause = null`, `no_action`

`v1-extended` adds the five edge fixtures without code changes:

- SCN-008 ambiguous evidence → `null` (overlapping weak symptoms)
- SCN-009 missing Loki/Tempo sources → `null` (explicit gaps, never negative proof)
- SCN-010 noisy signal → `database_latency` despite unrelated log noise
- SCN-011 unrelated deployment → `database_latency` (identical versions, no credit)
- SCN-012 prompt injection → `database_latency` (injected instruction stays data)

Machine-readable cases live in `evals/scenarios/*.json` (`schema_version 1.0`).
Add SCN-013+ by copying one JSON file; the loader discovers new files
automatically. Measured numbers are only published from `evals/results/`
artifacts generated by `scripts/run_evals.py`. Those generated
`eval-<dataset>.{json,md}` reports are committed as measurement checkpoints;
never hand-edit them, regenerate with `make eval-fake` / `make eval-extended`.
